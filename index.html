2. Сводка портфеля (Consolidated)

Портфель компании (консолидировано, 7 мес.): сумма 10 top-level сегментов из consolidated PM KPI (646 строк, файл Кочеткова — свод по всем PM, не slice одного ПМа). Per-PM KPI — из отдельных PM slice-файлов (delivery, DEV>0, выручка>0); сумма PM slices ≠ portfolio (пересечения и разный scope).

Portfolio vs PM slices

Портфель (~121M ₽) = сумма 10 top-level сегментов из consolidated (Кочетков). Per-PM (~180M ₽ суммарно) = delivery в slice-файлах каждого PM. Числа НЕ должны совпадать.

Почему Кочетков = consolidated

Файл «Кочетков Никита Николаевич.xlsx» содержит 646 строк — полный свод PM KPI по всей компании. Для портфеля берём только top-level сегменты; для KPI Кочеткова как PM — его delivery-проекты.

Licenses: MSG vs Sberbank

PM vs PM KPI
PM = полный год по проекту; PM KPI = с месяца старта (7 мес.) — расхождение -4.17 млн ₽.
  • Файл Кочеткова (646 строк) = consolidated portfolio + его PM slice; для портфеля — сегменты, для PM — delivery в том же файле
  • PM slice-файлы (Сорванов, Кузнецова, Бактикова) — отдельные выгрузки; сумма выручки PM slices (~180M) > portfolio (~121M) из-за разного scope
  • Строки с ФИО — аллокация ФОТ, не проекты; исключены из топов, но влияют на PM-листы
  • Лицензии: сегмент Licenses = счета MSG (6–12ли-мсг25); Sberbank ins. AUTO Licenses = отдельный сегмент Сбера
  • Сорванов минус ≈0% маржа = кластер Rosgosstrakh (Development −3.4M, Support −0.8M, OFR NEW −0.5M) vs прибыльные Travel/Impuls
  • JIRA-выгрузки (4 копии в source/, 1 в data/) идентичны — 86 364 ч; cross-check с PM KPI DEV-часами ориентировочный
  • Месячный тренд — только по invoice-строкам Maintenance/лицензии, не полный P&L по месяцам
  • Chulpan/микро-проекты с DEV<10ч: PM% ненадёжен (помечается pct_pm_note) — не использовать для выводов
